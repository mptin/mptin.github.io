# ЛР 1. Статический сайт на MkDocs и публикация на GitHub Pages

## Цель работы

* Освоить создание статического сайта генератором документации MkDocs.
* Организовать структуру портфолио лабораторных работ.
* Изучить базовые принципы работы с Git и GitHub.
* Развернуть сайт через GitHub Pages на домене вида `username.github.io`.
* Настроить тему оформления и конфигурационный файл `mkdocs.yml`.

## Задание

Основная часть: создать публичный репозиторий, настроить GitHub Pages на
публикацию из каталога `/docs` ветки `main`, создать виртуальное окружение,
установить MkDocs, настроить `.gitignore`, создать сайт командой
`mkdocs new source`, собрать его в `/docs` и отправить в репозиторий.

Самостоятельная часть: выбрать и подключить тему оформления, настроить
`mkdocs.yml` (название, тема, меню через `nav`), создать страницы (главная,
«Об авторе», раздел «Лабораторные работы» с отдельной страницей на каждую
работу и единым шаблоном отчёта), обеспечить навигацию.

## Реализация

### Структура репозитория

```
mptin.github.io/
├── .gitignore
├── README.md
├── source/              # исходники сайта
│   ├── mkdocs.yml
│   └── docs/
│       ├── index.md     # главная
│       ├── about.md     # об авторе
│       └── LR-1.md ... LR-10.md
└── docs/                # собранный сайт (его публикует GitHub Pages)
```

Исходники и результат сборки лежат в разных каталогах: в `source/` markdown,
в `docs/` готовый HTML. GitHub Pages умеет публиковать из `/docs`, поэтому
отдельная ветка `gh-pages` не нужна.

### Команды

```bash
python -m venv .venv
source .venv/bin/activate
pip install mkdocs mkdocs-material

mkdocs new source          # создать проект
cd source
mkdocs serve               # локальный просмотр на http://127.0.0.1:8000
mkdocs build -d ../docs    # собрать сайт в /docs корня репозитория
```

### Конфигурация `mkdocs.yml`

```yaml
site_name: Портфолио — Программирование на Python
site_url: https://mptin.github.io/

theme:
  name: material
  language: ru
  features:
    - navigation.sections
    - navigation.top
    - content.code.copy
  palette:
    - media: "(prefers-color-scheme: light)"
      scheme: default
      primary: indigo
    - media: "(prefers-color-scheme: dark)"
      scheme: slate
      primary: indigo

nav:
  - Главная: index.md
  - Об авторе: about.md
  - Лабораторные работы:
      - ЛР 1. MkDocs и GitHub Pages: LR-1.md
      - ЛР 2. NumPy: LR-2.md
      # ... остальные работы
```

## Результаты

Сайт опубликован, страниц получилось 12: главная, «Об авторе» и десять работ.
Меню организовано иерархически через `nav`.

### Почему Material

Задание допускает любую подходящую тему и называет в примерах `dracula` и
`material`. Я выбрал Material for MkDocs. Причины по убыванию важности:

| Критерий | Зачем это портфолио |
|---|---|
| Поддержка русского языка | `language: ru` переводит интерфейс и включает русскую морфологию в поиске |
| Встроенный полнотекстовый поиск | десять отчётов с таблицами, без поиска по ним неудобно ориентироваться |
| Адаптивная вёрстка | в отчётах широкие таблицы метрик, их нужно читать и с телефона |
| Светлая и тёмная темы | переключаются автоматически по системной настройке |
| Подсветка синтаксиса и кнопка копирования кода | в отчётах много листингов Python |
| Блоки `admonition` | выделяют замечания, не ломая структуру текста |
| Активная поддержка | самая популярная тема MkDocs, подробная документация |

`dracula` даёт в основном цветовую схему: ни поиска, ни адаптивной вёрстки,
ни блоков-примечаний там нет. Для портфолио с большим объёмом текста мне
важнее была функциональность.

### Где я спотыкался

!!! note "Почему страницы названы `LR-2.md`, а не `lab_02.md`"
    В задании ЛР 2 требуется, чтобы отчёт открывался по адресу вида
    `username.github.io/LR-2`. MkDocs по умолчанию работает в режиме
    `use_directory_urls: true` и превращает файл `LR-2.md` в
    `LR-2/index.html`, что даёт ровно нужный адрес `/LR-2`. С именем
    `lab_02.md` получился бы адрес `/lab_02`, и требование не выполнилось бы.

!!! warning "Каталог `/docs` нельзя добавлять в `.gitignore`"
    Собранный сайт публикует GitHub Pages, значит он обязан попадать в
    репозиторий. В `.gitignore` идут только виртуальное окружение,
    `__pycache__` и служебные файлы ОС.

!!! note "`mkdocs build` очищает каталог назначения"
    Команда `mkdocs build -d ../docs` перед сборкой удаляет содержимое
    `docs/`. Руками туда ничего класть нельзя, всё для публикации должно
    лежать в `source/docs/`.

## Выводы

Статический сайт для портфолио удобен тем, что у него нет ни серверной части,
ни базы данных, ни расходов на хостинг: набор HTML-файлов отдаётся напрямую с
GitHub.

Разделение «исходники / сборка» оказалось полезнее, чем я ожидал. Правится
только markdown в `source/docs/`, `docs/` пересобирается одной командой, и
случайно отредактировать сгенерированный HTML просто невозможно.

Про `nav` стоит сказать отдельно. Без него MkDocs строит меню автоматически
по алфавиту имён файлов, и для десяти работ это дало бы неверный порядок:
ЛР 10 оказалась бы между ЛР 1 и ЛР 2.
