## Реализация

Инструменты: requests для HTTP-запросов, BeautifulSoup для разбора HTML.

```python
REQUEST_DELAY = 0.7  # секунд между запросами


def get_soup(url):
    """Скачать страницу и разобрать её в объект BeautifulSoup."""
    time.sleep(REQUEST_DELAY)
    response = requests.get(url, headers=HEADERS, timeout=30)
    response.raise_for_status()
    return BeautifulSoup(response.text, 'html.parser')
```

Разбор страницы новости учитывает вариативность вёрстки:

### Где было легко ошибиться

!!! warning "robots.txt запрещает раздел /search/"
    Первое, что стоит проверить перед скрапингом. У news.itmo.ru стоит
    `Disallow: /search/`, а именно через `/ru/search/?search=...` проще всего
    искать новости по запросу. Поэтому сбор построен на ленте главных
    новостей `/ru/main_news/`, она не запрещена.

!!! danger "«0 ошибок» ещё не значит, что данные верные"
    Самая тонкая ошибка в работе. Естественный шаблон отбора ссылок это
    `/(\d+)/?$`, то есть «адрес, заканчивающийся числом». Под него попадают и
    анонсы мероприятий вида `/ru/announce/124118/`.

    Исключения при этом не возникает. Страницы анонсов открываются нормально,
    но свёрстаны иначе: ни счётчика просмотров, ни блока со статьёй. В
    таблице появились строки с пустым текстом и пропусками в просмотрах, а
    программа отрапортовала «успешно, 0 ошибок».

    Заметил только когда проверил заполненность полей после сбора: `views`
    заполнено на 94.7%, минимальная длина текста ноль. После ужесточения
    шаблона до `/news/(\d+)/?$` заполненность всех полей стала 100%.

!!! warning "Теги лежат в `ul`, хотя напрашивается `div`"
    Естественный вариант `soup.find('div', {'class': 'tags'})` вернёт `None`,
    молча, без исключения, и теги просто потеряются. Искать надо по классу,
    не указывая тег: `soup.find(class_='tags')`. На всякий случай сделан
    запасной путь через мета-теги `<meta property="article:tag">`.

!!! note "Счётчик просмотров спрятан внутри тега `<time>`"
    ```html
    <time datetime="2026-09-01T19:18:10+03:00">
      1 Сентября 2026, 19:18<span class="timezone">UTC+3</span><span class="icon eye">5659</span>
    </time>
    ```
    Из-за этого `time.get_text()` возвращает `1 Сентября 2026, 19:18UTC+35659`:
    дата, часовой пояс и просмотры слипаются в одну строку. Дату надо брать из
    атрибута `datetime`, там она в формате ISO 8601.

!!! note "`quoting=csv.QUOTE_ALL` обязателен"
    В текстах новостей есть запятые, кавычки и переводы строк. Без
    принудительного экранирования файл при обратном чтении съезжает по
    столбцам.

!!! note "140 ссылок из ленты дали 90 уникальных новостей"
    Одна и та же новость попадает в ленту на разных страницах (закреплённые,
    «Главное»). Дубликаты убираются через `drop_duplicates(subset='id')`.

### Вежливый скрапинг

Между запросами пауза 0.7 секунды, передаётся `User-Agent`, глубина обхода
ограничена константой `MAX_PAGES = 10`. Каждый запрос обёрнут в
`try / except`: одна недоступная страница не должна уничтожить весь результат.

## Выводы

`robots.txt` стоит смотреть до того, как написана первая строка парсера. У
меня он поменял источник данных целиком.

После сбора обязательно надо проверять полноту данных. Молчаливые пропуски
опаснее явных ошибок: программа отработала успешно, а 5% строк оказались
мусором, и без проверки заполненности я бы этого не увидел.

Вариативность вёрстки оказалась основной сложностью. Один и тот же сайт
использует разные теги и классы для одного и того же содержимого, так что
селекторы приходится перебирать по очереди и держать наготове запасные
источники.

И про вежливость: паузы, `User-Agent`, ограничение объёма. Обход всей ленты
означал бы тысячи запросов к чужому серверу.
